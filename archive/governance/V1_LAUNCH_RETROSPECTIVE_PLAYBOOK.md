# v1 Launch and Retrospective Playbook

> Defines the launch-day sequence for Atlas Lattice v1.0 and the full retrospective that follows.

status: candidate

---

## Launch Objectives

The v1.0 launch should do four things:

1. Publish a coherent public release
2. Demonstrate that milestone criteria were actually met
3. Capture community response and operational learnings
4. Convert the launch into the next planning cycle

---

## Launch Sequence

| Step | Action | Evidence |
|------|--------|----------|
| 1 | Final scorecard confirmation | Updated `WORLDCLASS_SCORECARD_BASELINE.md` |
| 2 | Tag and publish release | Git tag + GitHub release |
| 3 | Publish State of the Lattice report | `STATE_OF_LATTICE_REPORT_TEMPLATE.md` successor artifact |
| 4 | Publish changelog digest | `CHANGELOG_DIGEST_V1_LAUNCH.md` |
| 5 | Publish press/media kit links | `PRESS_MEDIA_KIT.md` |
| 6 | Announce in Discussions and public channels | Discussion thread + announcement links |
| 7 | Open retrospective note | `V1_LAUNCH_RETROSPECTIVE_YYYY_MM_DD.md` |

---

## Retrospective Questions

The retrospective must answer:

1. What worked unusually well in the launch?
2. What failed, slipped, or created avoidable friction?
3. Which public signals showed real adoption or trust?
4. Which parts of the v1.0 criteria were barely met versus strongly met?
5. What should become the first priorities of the post-v1 roadmap?
