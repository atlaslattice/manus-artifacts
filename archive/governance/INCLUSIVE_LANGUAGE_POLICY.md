# Inclusive Language Policy

> Defines the Atlas Lattice standard for inclusive, non-exclusionary language across all documentation and communication.

status: candidate

---

## Commitment

Atlas Lattice is a public, open-source gift to the world. Our language must be welcoming to all contributors regardless of background, nationality, ability, gender, religion, or identity.

---

## Language Rules

### 1. Avoid Ableist Language

| Avoid | Use instead |
|-------|------------|
| "the blind spot" | "the gap", "the overlooked area" |
| "sanity check" | "quick check", "validation" |
| "crazy/insane" (informal) | "complex", "unusual", "unexpected" |
| "dummy value" | "placeholder value", "example value" |
| "crippled/lame" | "limited", "degraded" |

---

### 2. Use Gender-Neutral Language

| Avoid | Use instead |
|-------|------------|
| "he/she" | "they" |
| "manpower" | "labor", "staff", "capacity" |
| "chairman" | "chair" |
| "blacklist / whitelist" | "deny list / allow list" |
| "master / slave" | "primary / replica", "controller / worker" |

---

### 3. Avoid Culturally Exclusionary References

- Avoid idioms that don't translate across cultures
- Avoid references to alcohol, gambling, or practices that may be culturally sensitive in some regions
- Use examples that are globally accessible (use ISO dates, not US-specific date formats; use "10,000" not "10K" in formal specs)

---

### 4. Avoid Hostile or Combative Framing

- Prefer collaborative framing: "When you encounter an error" not "When you fail"
- Prefer non-military metaphors where possible (acceptable exceptions: "campaign board" is explicit in the Aetherforge game context)
- Prefer "expected behavior" and "unexpected behavior" over "correct" and "wrong"

---

### 5. Non-Hostile Refugee and Migration Language

Atlas Lattice explicitly adopts non-hostile, welcoming framing when discussing:
- Knowledge migration (data migration, format migration)
- Archival workflows (nothing is "purged" without notice; prefer "archived" or "quarantined")
- Community participation (no one is "excluded"; contributors are "welcomed" or "not yet onboarded")

---

## Enforcement

Inclusive language is a code review criterion for PRs that touch documentation. Reviewers should note violations and request corrections. Violations are not blocking if minor, but patterns of violations warrant attention.

---

## Updating This Policy

Language norms evolve. This policy is reviewed annually as part of the annual accessibility audit. Proposed changes go through the standard RFC process.
