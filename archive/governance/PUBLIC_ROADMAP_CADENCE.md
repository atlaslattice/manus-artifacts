# Public Roadmap Cadence

> Defines how Atlas Lattice communicates its public roadmap and maintains community alignment.

status: candidate

---

## Roadmap Philosophy

The Atlas Lattice roadmap is public by default. Contributors and users deserve to understand where the project is headed and why. A visible roadmap:
- Attracts contributors who want to work on the right things
- Prevents duplicate work
- Creates accountability and momentum

---

## Roadmap Artifact

The primary roadmap is the **Aetherforge 144-Mission Campaign Board** at `projects/aetherforge-144-task-campaign-2026-05-27.md`. This is public, tracked on GitHub, and updated after each wave.

Supplementary roadmap: the **Next-144 Execution Taskboard** at `projects/aetherforge-next144-taskboard-2026-05-28.md`.

---

## Roadmap Update Cadence

| Update type | Frequency | Owner |
|------------|-----------|-------|
| Task completion update | After each wave sprint | Council / agent executing the wave |
| Quarterly roadmap review | Every 3 months | @atlaslattice |
| Annual roadmap renewal | Annually | @atlaslattice + council |

---

## Quarterly Roadmap Review Process

1. Review progress against the 144 campaign
2. Assess whether waves ahead are still the right priorities
3. Reprioritize tasks if context has changed
4. Publish a "roadmap update" GitHub Discussion summarizing changes

---

## How to Influence the Roadmap

Contributors can influence the roadmap by:
1. Opening a Feature Request issue (see Contributor Templates Standard)
2. Starting a discussion in GitHub Discussions (Q&A or Ideas category)
3. Proposing an RFC for larger changes

All input is considered. @atlaslattice makes final prioritization decisions.

---

## Roadmap Signals

The roadmap uses visual signals:
- ✅ Complete
- 🔄 In progress
- ⭕ Not started
- ❄️ Frozen / deprioritized
- 🚀 Accelerated / high priority
