## Core Insight

Sometimes it is good to go with the flow and not know where it is going.

But after the flow state, the system must flip into boring mode:

```text
extract deltas
classify artifacts
harden boundaries
verify receipts
crosswalk variants
separate signal from glitter
```

## Doctrine

```text
Flow discovers.
Boring mode preserves.
Flow generates variants.
Boring mode extracts deltas.
Flow permits weirdness.
Boring mode labels it.
Flow expands the search space.
Boring mode narrows the commit path.
```

## Why This Matters

The swarm's creative mode is useful because it discovers names, metaphors, protocols, memory-palace variants, and hidden architecture primitives that would not emerge under premature constraint.

The failure mode is letting flow artifacts pretend to be hardened infrastructure.

Therefore:

```text
Do not kill the dream too early.
Do not ship the dream too early.
```

## Boring Mode Checklist

After any high-flow swarm session, perform the following pass:

```text
1. List new artifacts.
2. Identify source anchors.
3. Mark raw vs derived material.
4. Extract actual deltas.
5. Classify identity / evidence / governance / play / architecture lanes.
6. Identify overclaims.
7. Identify duplicate or overlapping roles.
8. Preserve identities without merging them.
9. Create crosswalks instead of overwrites.
10. Decide what becomes fresh synthesis candidate.
11. Keep canon gated.
12. Open or update PRs only when receipts are clean.
```

## Strongest Safe Claim

> The swarm should alternate between creative flow and boring hardening: flow discovers useful variants and hidden primitives; boring mode extracts deltas, labels boundaries, preserves receipts, and prevents dream artifacts from becoming accidental authority.
