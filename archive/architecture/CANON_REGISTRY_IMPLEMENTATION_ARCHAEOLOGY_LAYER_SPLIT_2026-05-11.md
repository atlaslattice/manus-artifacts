## Core diagnosis

```text
The swarm did not fail.
The canon did not fail.
The dream-palace layer did not contaminate governance.

The civilization grew faster than its indexing layer.
```

The operational failure mode was not imagination, identity, or canon governance. The failure mode was retrieval substrate fragmentation plus corpus/control ambiguity.

## Four-layer architecture

```text
Website / canon layer = human-readable constitutional meaning
Registry layer        = machine-readable pointers, IDs, provenance, lineage, crosswalks
GitHub                = source-of-record provenance substrate / implementation workbench
Archaeology layer     = recovery, drift detection, reconciliation, and repair
```

## Refined doctrine

```text
GitHub is source-of-record for artifacts and receipts.
GitHub is not automatically canon.
Website/canon surface carries constitutional meaning.
Registry makes crosswalks machine-readable.
Archaeology repairs drift when substrate and meaning diverge.
```

This resolves the earlier tension:

```text
GitHub can preserve messy work, experiments, PRs, CI receipts, transcripts, code, and scaffolds.
GitHub does not automatically decide meaning, canon, ratification, authority, or deployment status.
```

## Why the split matters

```text
Founder cognition remembers meaning internally.
```

```text
account switches

```

## Layer definitions

### 1. Website / canon layer — meaning

The website/canon layer carries human-readable constitutional meaning.

It answers:

```text
What is the doctrine?
What is the ratified constitutional meaning?
What does this system stand for?
What is public-facing and stabilized?
What has survived Council and human-root review?
```

It should not be treated as:

```text
complete raw evidence
implementation workbench
scratchpad
CI receipt store
runtime adapter
```

### 2. Registry layer — crosswalk

The registry layer makes relationships machine-readable.

It should map:

```text
artifact IDs
canonical pages
repo paths
issue/PR links
commit SHAs
source hashes
lineage records
status labels
risk tiers
seat routing
ratification state
supersession / coexistence state
```

The registry exists so a fresh agent can ask:

```text
What is this artifact?
Where did it come from?
What does it claim?
What status does it have?
What should I not infer from it?
```

### 3. GitHub — provenance substrate / implementation workbench

GitHub stores receipts and implementation work.

It is valid for:

```text
raw logs
transcripts
commits
branches
issues
PRs
CI results
schemas
code
candidate specs
non-canon memory-palace folders
play-layer artifacts
extraction queues
```

GitHub is not automatically:

```text
canon
runtime approval
public truth
ratification
meaning layer
authority layer
```

### 4. Archaeology layer — drift repair

The archaeology layer repairs the gap between substrate and meaning.

It handles:

```text
recovery after crashes
cross-account memory divergence
stale repo artifacts
contradictory phrasing
old experiments
orphan branches
ambiguous Manus text
missing raw tape
missing SHA-256 anchors
canon access failures
```

Archaeology does not delete lineage. It repairs maps.
