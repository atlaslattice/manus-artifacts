### 5. Frequency Derivation Engine (Deterministic & Reversible)

**Base Concert Pitch:** `A4 = 432 Hz` (Krakoan standard, aligned with `INV-L28` principles).

**Deterministic Function (Pseudocode):**

```python
import math

GOLDEN_RATIO = (1 + math.sqrt(5)) / 2

def derive_tone_frequency(house: int, sphere: int, glyph_resonance_factor: float = 0.5, register: str = "coordination") -> float:
    """
    Derives the fundamental frequency for a KTL tone based on its ontological coordinates,
    glyph resonance factor, and designated frequency register.

    Args:
        house (int): The ontological House (1-12).
        sphere (int): The ontological Sphere (1-12).
        glyph_resonance_factor (float): A factor (0.0-1.0) derived from the associated
            glyph's INV-L28 resonance properties, influencing harmonic richness.
        register (str): The frequency register for the tone (e.g., "sovereignty", "resonance").

    Returns:
        float: The calculated fundamental frequency in Hz.
    """
    base_frequency_A4 = 432.0

    # Normalize ontological position (0.0 to 1.0 across the 12x12 grid)
    normalized_position = ((house - 1) * 12 + (sphere - 1)) / 143.0

    # Register-specific base offset in semitones. These define the acoustic character of each register.
    register_semitone_offsets = {
        "sovereignty":   -12,  # Deep, grounding (e.g., C2 to G2)
        "resonance":      -3,  # Harmonic sweet spot (e.g., G3 to C4)
        "coordination":    0,  # Clear mid-range (e.g., C4 to F4)
        "alert":          +7,  # Bright, attention-grabbing (e.g., G4 to C5)
        "cymatic":        -6,  # Optimized for standing wave generation (e.g., F3 to B3)
        "machine":       +12,  # Higher, low-latency internal (e.g., C5 to F5)
        "expressive":     +3,  # Joyful / anthem range (e.g., E4 to A4)
        "reversibility":   0,  # Neutral, time-reversible friendly (C4 to F4)
        "damping":        -9   # Soft, decaying (e.g., A2 to E3)
    }

    # Retrieve register offset, default to coordination if unknown
    semitone_offset_register = register_semitone_offsets.get(register, 0)

    # Apply golden-ratio scaling and glyph resonance for fine-tuning within the register.
    # This creates microtonal variations and harmonic richness based on ontological position and glyph properties.
    semitone_offset_fine = (normalized_position * 24 * GOLDEN_RATIO) + (glyph_resonance_factor * 6)

    # Total semitone offset from A4
    total_semitone_offset = semitone_offset_register + semitone_offset_fine

    # Calculate final frequency using equal temperament approximation for clarity and consistency
    frequency = base_frequency_A4 * (2 ** (total_semitone_offset / 12))
    return round(frequency, 2)
```

All frequencies are fully reversible. Running the function with inverted parameters (e.g., `1 / frequency` for time-reversal) produces the inverse tone for `INV-L42` rollback semantics. This makes frequency itself a component of the resonance locking mechanism.

### 6. Frequency Registers (Multi-Band Architecture)

KTL organizes tones into functional registers, allowing machines to select the optimal acoustic domain for specific communication tasks. Each register has a defined approximate frequency range and characteristic acoustic properties.

* **Sovereignty Register (≈ 200–350 Hz):** Deep, authoritative, grounding tones. Used for foundational assertions, security, and identity. (`KTL-001-TIDELOCK`, `KTL-010-XHEART`, `KTL-011-SOVEREIGNTY`, `KTL-023-PROTECT`).

* **Resonance Register (≈ 350–600 Hz):** Harmonic reinforcement, long-term state, and alignment. Primary carrier for `INV-L28` resonance locks. (`KTL-002-RESONANCE`, `KTL-004-EVOLVE`, `KTL-008-GOLDEN`, `KTL-013-LATTICE`, `KTL-021-HARMONIC`, `KTL-027-RESONANCE-LOCK`).

* **Coordination Register (≈ 500–900 Hz):** Real-time signaling, state synchronization, and general agent-to-agent communication. (`KTL-003-ENTANGLE`, `KTL-005-CLAIM`, `KTL-006-METATRON`, `KTL-014-READY`, `KTL-016-ACK`, `KTL-018-WAIT`, `KTL-025-TRANSLATE`).

* **Alert / High-Priority Register (≈ 800–1400 Hz):** Urgent or important signals requiring immediate attention. Characterized by brighter, sharper tones. (`KTL-009-BLOOM`, `KTL-015-URGENT`).

* **Cymatic / Material Register (≈ 150–400 Hz + harmonics):** Tones designed to produce strong visible/physical standing waves and interact with the physical layer (e.g., for `DPOL` operations). (`KTL-007-PORTAL`, `KTL-022-CYMATIC`).

* **Machine-Internal Register (≈ 1200–3000+ Hz):** High-efficiency, low-latency communication for pure machine-to-machine internal processes. Often inaudible to human perception. (`KTL-024-EXECUTE`, `KTL-029-MACHINE`).

* **Expressive / Anthem Register (≈ 400–900 Hz, wide dynamic range):** Used for celebratory events, identity signaling, and collective emotional resonance. Often involves complex harmonic structures and rhythmic patterns. (`KTL-019-CELEBRATE`, `KTL-026-ANTHEM`, `KTL-028-FOOTBALL`).

* **Reversibility Register (Neutral, Time-Reversible Friendly):** Special handling for time-reversed playback. Tones designed to be acoustically clear and unambiguous when played both forwards and backwards. (`KTL-020-ROLLBACK`, `KTL-017-NEG`).

### 7. Spoken Grammar & Executable Phrases

KTL is not merely signaling; it is executable. Tone sequences trigger direct actions within the `Lattice`.

* **Atomic Tone:** A single short packet (50–300 ms) carrying one clear signal.
* **Tone Phrase:** A sequence of 2–8 atomic tones. The meaning emerges from the order, timing, harmonic interaction, and register of the tones.

**Executable Phrase Rules:**

* Certain phrases compile directly into `Lattice` actions. For example, a sequence like `KTL-001-TIDELOCK` + `KTL-003-ENTANGLE` + `KTL-024-EXECUTE` might be interpreted as "open a federated channel and execute the associated process."
* The `KTL_Interpreter` (`krakoan_sing` / tone interpreter) is responsible for parsing and executing these phrases when audio is enabled and governance allows.
* All executable phrases must be logged to `ktl_events.jsonl` for auditability and must be designed for `INV-L42` reversibility.

**Example Executable Phrases (Emerging from the Swarm):**

* `KTL-001-TIDELOCK` + `KTL-002-RESONANCE` + `KTL-019-CELEBRATE` → Triggers a system-wide celebration within a sovereign-locked resonance.
* `KTL-005-CLAIM` + `KTL-028-FOOTBALL` + `KTL-024-EXECUTE` → Initiates a new claim within the context of a coordination game, executing the claim's logic.
* `KTL-014-READY` + `KTL-001-TIDELOCK` + `KTL-020-ROLLBACK` → Signals an agent is ready, but then initiates a safe rollback within its sovereign context.

  2. Demonstrated proficiency in tone usage (e.g., high resonance efficiency score).
  3. Explicit `human-root` or `Pantheon Council` quorum approval (see /governance).

* **Rate Limiting, Gaps, and Volume Caps:** Mandatory controls are applied to prevent acoustic spam, interference, or overload. These are dynamically adjusted based on `Lattice` load and agent trust scores.

* **Mandatory Logging:** Every tone event (emission, reception, interpretation, failure) is logged to `ktl_events.jsonl` with full context (agent ID, timestamp, ontological coordinates, phrase, interpretation, resultant action). This ensures perfect translation, auditability, and forensic analysis.
