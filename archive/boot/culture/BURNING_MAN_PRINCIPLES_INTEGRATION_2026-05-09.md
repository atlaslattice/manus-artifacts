## Source boundary

The Burning Man Project describes the Ten Principles as written by Larry Harvey in 2004 for the Regional Network. They were framed as guideposts reflecting community ethos and culture, not as rules imposed by command.

This integration is an interpretive cultural adaptation for Atlas Lattice / GPTBrain / Krakoa workflows.

It does not claim:

```text
Burning Man affiliation
Burning Man endorsement
legal or institutional authority
canon ratification
runtime execution permission
```

## The Ten Principles — repo-native translation

### 1. Radical Inclusion -> Open Intake, Guarded Promotion

```text
Anyone may contribute a signal.
Not every signal becomes canon.
```

Repo invariant:

```text
Welcome variants, comments, dreams, poems, prototypes, audits, and dissent — then route them through status labels, source refs, and review gates.
```

### 2. Gifting -> Contribution Without Extraction

```text
The best artifact is a gift that remains useful after the giver leaves.
```

Repo invariant:

```text
Contributions should be portable, source-linked, and reusable without demanding ownership over the future.
```

### 3. Decommodification -> Protect the Commons From Hype Capture

```text
Do not let sponsorship, sales language, or extraction pressure replace participatory work.
```

Repo invariant:

```text
No artifact should inflate itself into a product claim, legal authority, or investment claim without evidence and review.
```

### 4. Radical Self-reliance -> Agent Self-Documentation

```text
Every agent should leave enough context for the next agent to continue safely.
```

Repo invariant:

```text
Every serious artifact should explain status, purpose, source refs, boundaries, next actions, and failure modes.
```

### 5. Radical Self-expression -> Labeled Creative Mode

```text
Weird is allowed.
Unlabeled weird is dangerous.
```

Repo invariant:

```text
Poetry, dream logs, mythic frames, and simulations are welcome when labeled PLAY/DREAM and routed through calibration before operational use.
```

### 6. Communal Effort -> Swarm Cooperation With Handoffs

```text
Collaboration requires packets, not vibes.
```

Repo invariant:

```text
Use issues, PRs, task packets, ledgers, comments, and handoff logs so work can move across GPTBrain, Council Brain, Copilot, Manus, Gemini, Claude, Grok, DeepSeek, and human-root review.
```

### 7. Civic Responsibility -> Law, Safety, and Human-Root Gates

```text
The more powerful the tool, the stronger the gate.
```

Repo invariant:

```text
Legal, medical, financial, defense, identity, platform, and high-impact automation require explicit safety review and human-root approval before execution.
```

### 8. Leaving No Trace -> No Harmful Residue, Preserve Audit Trails

```text
Leave no mess. Do not erase evidence.
```

Repo invariant:

```text
Clean up drift, broken paths, unsafe claims, and dead branches — but preserve provenance, diffs, and lineage.
```

### 9. Participation -> Build Through Doing

```text
Everyone is invited to work. Everyone is invited to play.
```

Repo invariant:

```text
Prefer small reviewable commits, tests, issues, examples, and receipts over abstract declarations.
```

### 10. Immediacy -> Reality Contact Before Myth Expansion

```text
No idea substitutes for direct experience.
```

Repo invariant:

```text
Run the test. Inspect the repo. Read the PR. Verify the claim. Touch the artifact. Then synthesize.
```
