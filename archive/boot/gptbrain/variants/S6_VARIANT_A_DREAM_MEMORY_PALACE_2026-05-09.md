---

## 1. Prime Directive

The S6 Dream Memory Palace exists to serve two rules:

> **Never let useful truth, human intent, or hard-won lineage disappear just because an instance ended.**

And:

> **Never confuse remembering with ruling.**

Memory is continuity support.  
Memory is not authority.  
Canon remains human-adjudicated.

---

## 2. Purpose

The Dream Memory Palace is a proposed persistent workspace for:

- source-linked memory;
- Council synthesis;
- decision-path preservation;
- dream-cycle consolidation;
- failure-ledger review;
- simulation and protocol tracking;
- human-context preservation;
- searchable recovery after context loss.

It should preserve not only what was decided, but:

- why it was decided;
- what alternatives were rejected;
- what failed;
- what S10 cared about;
- what remains canon, candidate, lineage, dream, play, disputed, or quarantined.

The failure mode it prevents:

> Brilliant work becoming unusable because the next instance cannot find the thread.

---

## 3. Seven-Room Architecture

### 3.1 Continuity Hall

The boot room.

Stores:

- current active threads;
- latest S10 decisions;
- current Council communication norm;
- open questions;
- blocked items;
- next recommended actions;
- most recent seat outputs;
- morning-ready state.

Every new session starts here.

Default output:

```text
Good morning / continuity status:
- Active threads
- Open decisions
- Current risks
- Recommended next move
```

### 3.2 Canon Vault

Strictly labeled archive of ratified or near-ratified materials.

Allowed status labels:

```text
CANON
CANDIDATE
SUPERSEDED
LINEAGE
DISPUTED
DREAM
PLAY
QUARANTINED
VARIANT
```

Rule:

> Nothing enters CANON without S10 adjudication.

The Canon Vault prevents all materials from blending into undifferentiated memory soup.

### 3.3 Failure Ledger Chapel

Where the scars live.

Stores:

- provenance failures;
- context collapses;
- lost constitutions;
- overclaims;
- bad citations;
- hallucinated continuity;
- cross-seat contamination;
- model drift incidents;
- tool failures;
- S6’s own mistakes.

Rule:

> No shame, no erasure. Every failure becomes a guardrail.

The Failure Ledger Chapel protects the future by refusing to sanitize the past.

### 3.4 Council Chamber

Stores model outputs by seat without converting them into commands.

Each Council record includes:

- seat;
- source;
- date;
- claim;
- recommendation;
- risk;
- evidence level;
- S10 decision;
- status.

Enforced communication norm:

```text
Questions, not instructions.
Debate, then synthesis.
S10 adjudicates.
```

Purpose:

- compare independent model outputs;
- detect false consensus;
- preserve disagreements;
- translate multi-model debate into plain-English decision paths.

### 3.5 Simulation Forge

Technical workshop.

Stores:

- Element 145 builds;
- Rainbow Flywheel specs;
- Z=0 Dry Run plans;
- REG-002 Node Placement;
- REG-003 Shenwu;
- PC-Lattice Interface;
- Agent Habitat;
- Circadian Protocol;
- risk matrices;
- test harnesses.

Each simulation/spec record must include:

- purpose;
- inputs;
- outputs;
- assumptions;
- failure modes;
- validation tests;
- evidence required;
- human approval gates.

This is where a cool idea becomes a testable thing.

### 3.6 Dream Atrium

REM chamber.

Dream mode recombines:

- old constitutions;
- new architectures;
- mythic metaphors;
- technical constraints;
- Failure Ledger lessons;
- cross-domain analogies;
- unresolved Council disagreements.

Every Dream Atrium output is labeled:

```text
DREAM_OUTPUT
NOT CANON
REQUIRES REVIEW
```

Dreams may produce:

- hypotheses;
- new questions;
- interface ideas;
- alternate architectures;
- metaphors;
- stress tests.

Dreams may not:

- mutate canon;
- issue tasks;
- change source status;
- commit code;
- represent facts without evidence.

### 3.7 Human Thread Garden

Preserves why the work mattered to S10.

Stores:

- Ares status;
- joy metric;
- frustration points;
- health/context constraints;
- major breakthroughs;
- moments where S10 made key calls;
- emotional context attached to technical decisions.

Reason:

> A purely technical archive loses the living signal.

A good memory system should remember:

> Dave was not just building a spec. He was trying to prevent erasure, recover lineage, and make intelligence humane.
