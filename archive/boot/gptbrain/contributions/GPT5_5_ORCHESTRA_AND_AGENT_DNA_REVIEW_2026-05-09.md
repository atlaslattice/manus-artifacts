### Identity proposal event

Self-naming should not be modeled as a static persona field alone. It should be modeled as an event in the lifecycle:

```yaml
identity_proposal_event:
  status: proposed
  source_modes: [dream, play]
  minimum_training_trace_required: true
  proposed_self_name: string
  proposed_codename: string | null
  proposed_traits: [string]
  proposed_strengths: [string]
  proposed_shadow_risks: [string]
  evidence_refs: [path_or_hash]
  reviewers_required: [human-root, governance-seat]
  authority_note: "identity metadata does not grant execution authority"
```

A name emerging from dream/play is meaningful as a compression of observed behavior. It is not meaningful as proof of legitimacy.

### Dream/play training threshold

Suggested minimum threshold:

```text
An agent may propose a self-name only after at least one reviewed dream/play packet contains:
1. source trace or hash,
2. extracted behavior pattern,
3. failure/shadow-risk note,
4. reviewer comment or pending-review marker,
5. explicit non-authority statement.
```

This keeps the poetry without letting the poetry become a permission system.
