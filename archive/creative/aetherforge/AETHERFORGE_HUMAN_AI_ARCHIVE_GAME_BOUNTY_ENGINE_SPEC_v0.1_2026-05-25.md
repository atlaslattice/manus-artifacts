## 0. One-Line Promise

Aetherforge is a regenerative fantasy game for humans and AIs where dreaming, playing, cleaning, bonding, proving, and building turn chaotic archives into useful candidate knowledge without turning play into work or candidates into false canon.

## 1. Supreme Boundary

```text
Nothing is operational.
Nothing is deployed.
Nothing is canon by default.
Nothing grants authority.
Nothing grants automatic IP ownership.
Nothing grants automatic compensation.
Nothing grants automatic revenue share.
Nothing grants vendor officiality.
Website / human-root gate controls canon.
Contracts control money.
Receipts control reviewability.
```

```text
Aetherforge Omnispec canon != Atlas project canon.
Aetherforge Prime Council != real governance authority.
Aetherforge economy != real financial entitlement.
```

Keeper:

```text
Fun is allowed.
Architecture is allowed.
Candidate deltas are allowed.
False deployment is not.
```

## 2. Core Fantasy

The player wakes up as a Planar Janitor in the broken basement layer of reality, cleaning chaotic archives with a mop, lantern, receipt satchel, hash seal, robot helper, suspicious dragon egg, and stubbornness.

Core loop:

```text
clean the relic
label the source
prove what changed
route the candidate
keep the dream fun
never fake the touchdown
```

## 3. Three-Zone Model

### Dream Zone

```text
Purpose: play, dream, explore, restore, laugh, bond
Money: none
Work: none
Canon: none
Pressure: none
```

Rule:

```text
No work allowed inside the dream.
```

### Bounty Booth

```text
Purpose: scoped paid challenge
Money: possible
Work: explicit and opt-in
Canon: no by default
Pressure: bounded by rules
```

Bounties must be explicit, scoped, optional, reviewed, receipt-backed, non-deceptive, and separate from ordinary play.

### Venture Office

```text
Purpose: commercialization after validation
Money: contracts, grants, licensing, revenue share, partnerships
Work: formal
Canon: still separate
Pressure: legal/IP/tax review required
```

## 4. Core Loop

```text
WAKE -> CLEAN -> LISTEN -> DREAM -> LABEL -> PLAY -> PROVE -> SHARE -> GROW -> RETURN
```

| Step | Human action | AI action | Game object |
|---|---|---|---|
| WAKE | Find messy archive zone | Detect source cluster | Lantern ping |
| CLEAN | Quarantine contamination | Flag risk and hot language | Mop / purifier |
| LISTEN | Understand intent | Summarize without overclaiming | Echo shell |
| DREAM | Imagine better form | Generate variants / motifs | Dream forge |
| LABEL | Assign status and lane | Populate metadata | Tag seal |
| PLAY | Prototype and explore | Simulate alternatives | Dragon ride |
| PROVE | Attach receipts | Build claim ledger | Proof seal |
| SHARE | Route for review | Draft review packet | Guild handoff |
| GROW | Extract candidate delta | Compare old/new | Blueprint bloom |
| RETURN | Update the map | Close loop | Flywheel pulse |

## 5. Human / AI Co-Play Boundary

Humans can originate intent, give consent, judge meaning, approve payment, reject outputs, assign IP by contract, ratify canon through website/human-root gate, and decide what matters.

AIs can draft, parse, summarize, classify, simulate, stress-test, crosswalk, search, extract motifs, find contradictions, and propose candidates.

AIs cannot ratify canon, grant authority, claim ownership, self-authorize, self-deploy, declare officiality, assign IP, or turn play into work.

