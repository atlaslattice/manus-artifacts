# Toy Graph Walkthrough — Under 50 Lines

```text
STATUS: PUBLIC WALKTHROUGH CANDIDATE — NOT CANON
DEPLOYMENT: none
AUTHORITY: none
```

1. Start with a source.
2. A source can be a GitHub file, Drive doc, Notion page, chat export, PDF, or spreadsheet.
3. Give the source a passport.
4. The passport says where it came from and what status it has.
5. Then extract one claim.
6. A claim is something the source says.
7. The claim is not automatically true.
8. Attach evidence if available.
9. Evidence can be a file path, commit SHA, URL, hash, or export receipt.
10. If evidence is missing, create a MissingReceipt node.
11. Missing is not failure.
12. Missing is review pressure.
13. If two claims conflict, create a Contradiction edge.
14. Contradiction is not deletion.
15. Contradiction means review is needed.
16. Route the claim to a review lane.
17. Review lanes include Rootglass, Lucerna, Hashlight, TIDELOCK, Sable, Grok, and Human-root.
18. Review does not automatically ratify.
19. GitHub does not automatically canonize.
20. OpenAI/GPTBrain does not automatically authorize.
21. Claude-origin governance material is preserved but quarantined for adversarial review.
22. Dream/play outputs can create useful deltas.
23. Dream/play outputs are not proof.
24. The graph connects all these pieces.
25. The graph is inspectable.
26. The graph is forkable.
27. The graph is not a throne.
28. A graph edge is not promotion.
29. A cluster is not canon.
30. A central node is not authority.
31. Public candidate means safe to inspect.
32. Public candidate does not mean final.
33. Canon requires explicit human-root / website gate.
34. The toy graph shows the pattern.
35. Source → Claim → Evidence → Review.
36. If evidence is missing: Source → Claim → MissingReceipt → Review.
37. If claims conflict: Claim A → Contradicts → Claim B.
38. Nothing is erased casually.
39. Nothing self-promotes.
40. Everything remains reviewable.
41. The graph is the tape.
42. The tape is not the trophy.
