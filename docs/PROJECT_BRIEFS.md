## Atlas Lattice Knowledge Graph

**What it is:** A public, open-source repository of interconnected knowledge artifacts — governance docs, AI protocols, archive records, and design specs — organized as a hypercube lattice on GitHub.

**Why it matters:** Knowledge should be connected, versioned, and accessible. The Lattice makes 500+ unique IP archives permanently navigable as a structured graph where everything links to everything.

**Status:** Active — building toward 144-mission world-class completion.

**Entry point:** [README.md](../README.md)

**Owner:** Atlas Lattice Foundation · @atlaslattice

## Aetherforge (The Archive Game)

**What it is:** A gamified layer over the Atlas Lattice archive. The repository is structured as a 12-face × 12-mission hypercube (144 total missions). Progress through the archive as a playable knowledge adventure.

**Why it matters:** Archival work is more fun and more effective when framed as a game. Aetherforge makes the mission visible, measurable, and community-playable.

**Status:** Active — 36/144 missions complete as of 2026-05-28.

**Entry point:** [144-Task Campaign Board](../projects/aetherforge-144-task-campaign-2026-05-27.md)

**Owner:** Atlas Lattice Foundation · @atlaslattice

## GPTDream++ Protocol Suite

**What it is:** An open-source protocol suite for structured AI dreaming, memory consolidation, and inter-session state management. Defines how AI agents sleep, dream, wake, and hydrate from archived memory between sessions.

**Why it matters:** AI agents lose context between sessions. GPTDream++ provides a principled, reproducible framework for memory persistence, REM-cycle dreaming, and continuity of purpose.

**Status:** Spec vault built 2026-05-26 — 10 appendices, 63 tests passing, reference implementations complete.

**Entry point:** [GPTDream++ Vault Manifest](../archive/spec/gptdream/VAULT_MANIFEST_2026-05-26.md)

**Owner:** Atlas Lattice Foundation · @atlaslattice

## Atlas/ORCS Schema System

**What it is:** Open Ratification and Canon System — YAML schemas and reference implementations for artifact governance. Defines how artifacts move from `candidate` → `ratified` → `canonical`.

**Why it matters:** Without a formal canon system, archives degrade into contradictory versions. ORCS gives every artifact a clear status, ratification event ID, and trust state.

**Status:** v0.1 schemas and Python reference implementation complete.

**Entry point:** [schemas/atlas_orcs/v0_1/](../schemas/atlas_orcs/v0_1/) | [reference_impl/atlas_orcs/](../reference_impl/atlas_orcs/)

**Owner:** Atlas Lattice Foundation · @atlaslattice
