# Deprecation and Retirement Policy

Status: candidate policy (not canon)

## Core Principle

Deprecated artifacts are preserved in a log vault model rather than deleted.

## Deprecation Triggers

- Security risk in active use path
- Canon supersession by ratified replacement
- Structural incompatibility with current schema/governance model

## Required Deprecation Metadata

- reason for deprecation
- replacement artifact path (if available)
- effective date
- reviewer/authority reference

## Retirement Procedure

1. Mark artifact as deprecated/superseded in nearest index.
2. Add replacement link or explicit “no replacement” note.
3. Preserve artifact contents for historical and audit retrieval.
4. If sensitive exposure exists, redact sensitive fragments and document redaction rationale.

## Prohibited Action

- Silent deletion of historically relevant governance/provenance artifacts.
