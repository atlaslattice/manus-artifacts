# Anti-Confusion Terminology Notes

> **Status:** Candidate
> **Last reviewed:** 2026-05-28
> **Provenance:** Maintained in GitHub to reduce interpretation drift across docs and boards.

## Canonical substrate vs canon status

- **Canonical substrate:** GitHub is the durable source system where artifacts live.
- **Canon status:** A separate governance state that requires ratification.

An artifact can be in GitHub and still be candidate only.

## Candidate vs canon

- **Candidate:** Draft/proposed artifact; not yet ratified.
- **Canon:** Ratified artifact with governance approval.

Do not use these terms interchangeably.

## Board vs receipt

- **Board:** Planning and execution tracker.
- **Receipt:** Evidence links showing completed merged work and validation.

A task is not complete only because it appears on a board.

## Archive index vs docs index

- **Docs index (`/docs/README.md`):** navigation hub for docs pages.
- **Archive index (`/archive/README.md`):** entry to archival artifact lanes.

Use the docs index for orientation and the archive index for deep historical surfaces.

## Standard vs policy

- **Style guide/standard:** formatting and structure expectations.
- **Policy:** governance or compliance rule with normative constraints.

Do not place policy requirements only inside style guidance.
