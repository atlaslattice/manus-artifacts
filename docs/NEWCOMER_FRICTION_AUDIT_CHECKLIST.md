# Newcomer Friction Audit Checklist + Scoring
Status: Candidate
Date: 2026-05-28

Use this checklist to score first-time contributor and reader experience.

## Scoring model

- Score each item 0–2:
  - 0 = missing or broken
  - 1 = present but unclear / incomplete
  - 2 = clear, complete, and usable
- Total score bands:
  - 0–12: high friction (blocker)
  - 13–24: medium friction (needs targeted fixes)
  - 25–36: low friction (acceptable)

## Checklist (18 checks)

### Entry and orientation
1. Front door mission is visible (`README.md`)
2. Canon boundary is visible and understandable
3. Start path is obvious within 60 seconds
4. Domain map is obvious within 2 clicks
5. Active execution board is visible
6. Contribution path (questboard) is visible

### Navigation and traceability
7. Major domain folders have READMEs
8. Core docs cross-link to each other
9. No broken internal links on front-door surfaces
10. Key artifacts are reachable from navigation roots
11. Deprecated references route to preserved vault notes
12. Replacement pointers are explicit when available

### Validation and trust
13. Status labels are visible on key artifacts
14. Date labels are visible on key artifacts
15. Public validation commands are documented
16. Quality gate expectations are visible
17. Governance escalation path is visible
18. Weekly status cadence artifacts are published
