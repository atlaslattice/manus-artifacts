# Repository Architecture Overview

## Purpose

This document provides a one-page architecture map of the Manus Artifacts repository.

## Top-Level System Domains

- `/docs/` — Public navigation, taxonomy, and cross-domain reference maps.
- `/projects/` — Execution boards and project-specific implementation streams.
- `/archive/` — Historical, research, governance, and protocol artifacts.
- `/aluminum-os/` — Constitutional substrate and system architecture documents.
- `/sheldonbrain/` — Knowledge-substrate architecture and brain-model docs.
- `/bazinga/` — Middleware and launch protocol artifacts.
- `/council/` and `/council-reviews/` — Governance sessions and review records.
- `/.github/` — Contribution policy, issue/PR templates, CI workflows.

## Control Flow

1. Work is proposed through issues, project boards, or direct contribution PRs.
2. Changes are validated by repository hygiene and domain-specific checks.
3. Artifacts remain candidates unless explicitly ratified under governance policy.
4. Cross-links and indexes route readers from high-level maps to deep artifacts.

## Quality Layers

- **Documentation quality:** Readability, link integrity, taxonomy consistency.
- **Governance quality:** Canon boundary enforcement and provenance requirements.
- **Automation quality:** Workflow checks for formatting, links, and safety controls.
- **Knowledge graph quality:** Node/index consistency and relationship integrity.
