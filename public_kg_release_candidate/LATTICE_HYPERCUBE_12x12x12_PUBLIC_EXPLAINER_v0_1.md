## Purpose

This document explains the Atlas Lattice 12x12x12 hypercube as a candidate coordinate system for organizing knowledge, artifacts, claims, evidence, reviews, and public-safe releases.

It is not a completed scientific standard. It is not canon. It is not a deployment claim. It is a public-candidate ontology explainer for review.

## One-line summary

The lattice is a candidate map for making knowledge inspectable: every artifact should have coordinates, provenance, claims, receipts, review state, synthesis state, fossil state, and promotion boundaries.

## No single source of truth

Atlas Lattice does not use a single-source-of-truth model.

The operating model is:

- preserve many versions before synthesis
- preserve fossils and failed branches
- avoid hierarchy as a default organizing assumption
- keep raw logs, derived artifacts, reviews, contradictions, and missing receipts separately addressable
- synthesize only after adversarial review
- treat canon as downstream of human-root adjudication and website placement

A clean repository, a beautiful graph, a model consensus, or a polished document is not a final source of truth.

## What the 12x12x12 means

The 12x12x12 structure is a candidate hypercube model:

- 12 top-level houses or domains
- 12 subdomains per house
- 12 working lanes, states, modules, or review dimensions per subdomain

This gives a symbolic maximum of 1,728 coordinate cells. The number is useful because it is large enough to hold complexity, but structured enough to make gaps, contradictions, missing receipts, fossils, versions, and review states visible.

## What the lattice is

The lattice is a knowledge-graph coordinate system.

It can map source artifacts, raw exports, parsed packets, claims, evidence anchors, missing receipts, hash gaps, fossils, failed branches, review findings, contradictions, supersessions, quarantine decisions, public-candidate bundles, Pantheon review findings, human-root adjudications, and website canon placements.

## What the lattice is not

The lattice is not canon, truth by itself, a scientific standard by assertion, an authority engine, a hierarchy, a single source of truth, a replacement for human-root adjudication, proof that a repository is complete, proof that a source was fully exported, proof that a model output is safe for publication, or proof of OpenAI endorsement or integration.

## GitHub is the public shelf, not canon

GitHub is useful as a durable public receipt shelf for safe files, code, schemas, issues, review notes, CI checks, reproducible artifacts, fossils, and review history.

But GitHub is not canon by default.

A GitHub file can be source material, receipt, staging artifact, candidate explainer, review packet, public-safe demo, fossil, or test fixture.

Canon requires the full promotion route:

```text
many versions preserved
  -> fossils preserved
  -> adversarial Pantheon Council review
  -> human-root adjudication
  -> website placement
  -> canonical surface
```

## Receipts are not truth

A receipt proves that something exists, was logged, or was mirrored. It does not prove that the claim inside the receipt is true.

The graph should separate:

```text
source -> parsed artifact -> claim -> evidence anchor -> review finding -> adjudication -> website canon placement
```

This prevents truth laundering, where a clean-looking index accidentally makes unsupported claims look verified.

## Missing receipts are graph nodes

A missing receipt should not disappear into prose.

It should become a graph node:

```text
MissingReceipt -> blocks -> Claim / Artifact / Export / Review / Release
```

Likewise, missing hash becomes a HashGap node, partial export becomes ExportGap status, not found becomes a search result state, blocked dependency becomes a blocked_by edge, and failed branch becomes a fossil node.

## Promotion boundary

Human-root adjudication is required before any candidate becomes canon or public-release authorized. Pantheon Council adversarial review is required before adjudication for doctrine-level or public-canon claims.

The promotion path should look like:

```text
raw source
  -> parsed artifact
  -> many preserved versions
  -> fossil / failed branch preservation
  -> public-candidate packet
  -> adversarial Pantheon Council review
  -> human-root adjudication
  -> release gate
  -> website placement
  -> canon surface
```

No model consensus, graph centrality, GitHub receipt, single document, or beautiful synthesis can skip this boundary.
