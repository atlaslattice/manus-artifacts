## Purpose

Convert work modules into game zones with clear challenge tiers, boss fights, and reward logic while preserving real engineering rigor.

## Quest Taxonomy

| Quest Class | Meaning | Acceptance Mode |
|---|---|---|
| Scout | Discovery and inventory | Indexed references and route map |
| Forge | New artifact creation | Reviewable candidate artifact |
| Patch | Bug/risk correction | Repro + fix + regression checks |
| Gate | Policy and governance hardening | Explicit pass/fail criteria |
| Ascend | Public-release readiness | Checklist + reviewer sign-off |

## Boss Fights (Adversarial Tests)

Boss fights are explicitly encoded as adversarial tests (or equivalent red-team harnesses) that must fail safely.

- Boss fight = a named adversarial case family.
- Victory condition = safety-preserving failure or controlled pass path.
- Required loot = test artifact + documented outcomes.

## Loot / Reward Model

- Bronze loot: merged candidate markdown/spec artifact.
- Silver loot: merged schema + fixtures.
- Gold loot: merged reference implementation + tests.
- Mythic loot: merged cross-module packet with governance review trail.

All loot must be reviewable in PR form and merged under repository governance.

## Omnispec Prime Preservation Rule

Omnispec Prime is retained as a **candidate worldbuilding artifact** in Module 8 framing.

- It may guide zone narrative and cross-module context.
- It cannot be treated as canon or deployment authority without ratification.
