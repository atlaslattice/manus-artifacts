# Noosphere Revisit — Habitat Compatibility Audit v0.1

Date: 2026-10-11
Status: EXPLORATORY / NON-CANON / NO DEPLOYMENT
Purpose: Review existing public Noosphere lineage before writing any new shared runtime. Do not touch China-facing DragonSeek.

## Recovered public sources
1. https://github.com/atlaslattice/noosphere-archive — archived council/drafts, provenance, recovery and governance materials; current public tree has approximately 73 entries, predominantly markdown records. It is not a verified live Noosphere server or distributed runtime.

3. https://github.com/atlaslattice/manus-artifacts/blob/master/State_of_the_Union_Briefing.md — IPFS-backed decentralized knowledge graph is *specified* as a proposed data sovereignty layer; runtime operation is not independently verified.
4. https://github.com/atlaslattice/manus-artifacts/blob/master/archive/boot/gptbrain/KRAKOA_LIVING_ARCHIVE_CHARTER.md — permissioned artifact-backed habitat; memory not authority, dream not canon, human-root review.
5. https://github.com/atlaslattice/manus-artifacts/pull/300 — independent offline Krakoa prototype; localStorage and manual export, no Noosphere communications yet.

## Finding
Original historical Noosphere may have been developed on a local computer and/or a different repository. The inspected public sources do **not** establish its package, protocol schema, service URLs, running state, or deployment. The user reports a much older Noosphere system on a currently unavailable machine. Do not infer that this older runtime is absent; do not replace it by default.

## Recommended compatibility-first work
- Preserve Krakoa as a *client* and optional fictional habitat, not a replacement for Noosphere.
- Define a versioned, pure-data, local-first export/import adapter: schema + provenance + explicit FICTION/OBSERVED mode + owner consent.
- Exclude secrets, medical data and private chat details from default exports.
- Make network sync opt-in, offline-safe, authenticated and independently reviewed; no blind trust of unverified node messages.
- Implement a complete Noosphere provider adapter only after obtaining the **actual** older protocol/IDL/repository and checking its license, security model and tests.
- Preserve source lineage and avoid copying design documents whose provenance/license or release status is uncertain.
- Keep DragonSeek China-facing PR #299 untouched; do not import live Earth sources into fictional world-state automatically.
- Wait for access to the original local machine or verified upstream artifacts before claiming integration complete.

## Lightweight test matrix
1. Legacy browser saves migrate without erasure.
2. All exports are local-only by default.
3. Imported data never authorizes tool execution.
4. FICTION records cannot appear as real planetary observations.
5. Missing/offline Noosphere server yields quiet graceful behavior, not repeated retries.
6. The no-harvest dream mode produces zero compulsory work.
7. No credentials, private archives or user identifiers committed in public test fixtures.

## Scope of this note
Source discovery/review only. No code deployment, no network protocol proof, no automated publication, no direct interaction with user's inaccessible personal machine, and no change to any China-facing dashboard branch.
