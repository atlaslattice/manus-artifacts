# Codex Patch Discipline

**Status:** public candidate  
**Canon:** no  
**Deployment:** no  
**Authority:** none  

Codex-side work should only begin after repo identity, branch, license, raw export, and human permission are clear.

## Pre-patch requirements

- repo_id exists
- repo URL or local path exists
- default branch known or explicitly unknown
- license status declared or flagged
- raw/export status declared
- issue/task objective written
- no secrets or private content exposed
- patch scope bounded
- human-root permission present

## Patch rule

Codex may prepare or apply patches only through explicit repo discipline.

## Forbidden

- patching unknown repos
- modifying private/sensitive files without review
- treating patchability as deployment
- treating merged code as canon
- creating public claims from code presence

## Keeper line

Codex patches. It does not ratify.
