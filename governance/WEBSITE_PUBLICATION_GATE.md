# Website Publication Gate
Status: Candidate
Date: 2026-05-26

This checklist governs promotion of a GitHub artifact to a public website canon destination.
Website publication is a second trust boundary: an artifact can be visible in the repository yet still fail the public website gate.

## Entry criteria

Before website publication begins, confirm:

- the source artifact exists in GitHub and is the intended canonical substrate
- status is explicit and accurate
- steward ownership is clear
- the artifact is either canon or explicitly approved for candidate-stage public publication

## Content quality checks

- summary paragraph is understandable to a first-time reader
- terminology is defined or linked
- headings are structured and scannable
- outbound and internal links are valid
- sensitive claims are framed with appropriate caution

## Trust and governance checks

- canon claims match repository governance records
- no unresolved canon conflict exists
- provenance requirements are satisfied for high-impact claims
- public trust risks have been reviewed

## Publication checklist

- [ ] source path recorded
- [ ] lifecycle state confirmed
- [ ] summary text prepared
- [ ] metadata and version noted
- [ ] links tested
- [ ] steward sign-off recorded
- [ ] governance sign-off recorded for canon-bound pages

## Failure rule

If any trust-critical criterion fails, do not publish to the public website canon destination.
The repository artifact may remain visible as Candidate, but the website should not overstate its authority.
